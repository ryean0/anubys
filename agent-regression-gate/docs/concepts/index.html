    Concepts

    Two arms, repeated rollouts per arm, and one pooled status. The gate rule is non-inferiority, δ = 5 pp, at a 90% interval.

    On this page

    1. Arms
    2. The gate rule
    3. Four statuses

    Arms

    A run has two arms: baseline and candidate. The baseline is the agent already in production. The candidate is the one on the pull request.

    Each arm repeats the same scenarios. Those are repeated rollouts per arm. The suite status pools the arms. A single scenario does not pass or block the pull request on its own.

    The gate rule

    The gate rule is non-inferiority, δ = 5 pp, at a 90% interval. Pass when the lower bound is above −5 pp. Block when the upper bound is below −5 pp. Otherwise a valid run is Insufficient evidence.

    Gate spec. The rules are fixed. Computing them on real runs lands with Milestone B (target November 10). Today harness run runs rollouts and writes run_summary.json, not a verdict.

    The rule is the one the Gate page states. The rule is specified. The stats engine that computes it is planned for Milestone B (target November 10).

    Four statuses

    • Pass
    • Block. Orange means Block.
    • Insufficient evidence. It can carry a Likely regression warning. That warning is not a fifth status.
    • Invalid run. An invalid run isn't scored.

    Misses and fails

    agent_timeout and agent_error are fails. They score 0 and stay in the sample. A rollout that misses the expected outcome is a fail too.

    spend_ceiling is a live rollout that went over its dollar ceiling. It is recorded as status error and counts as an error: a failed rollout in the pass rate, scored 0. It is not a miss. A rollout that already ended as an infrastructure miss, such as http_5xx, stays a miss even if it also went over the ceiling.

    infra_timeout, rate_limit, http_5xx, ci_kill, and env_miss are misses. A miss is excluded from the score and counts toward the cap.

    Fails stay in the score. Misses are excluded.

    The cap is 5% of the scheduled rollouts on an arm. Exactly 5% still scores. Over the cap, the run is invalid_run and the status is Invalid run.

    Each scenario also needs a coverage floor of ceil(0.6 × scheduled) usable rollouts on both arms. That floor is separate from the miss cap.

    MDE

    MDE is the minimum detectable effect: the smallest gap this sample can separate from noise. It is not a status. The four statuses stay Pass, Block, Insufficient evidence, and Invalid run.

    Showing the MDE on the check is planned with Milestone B (target November 10). The roadmap lists cost per verdict and the per-family breakdown by October 29.
