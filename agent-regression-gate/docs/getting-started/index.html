    Getting started

    This page is for someone who wants to try Anubys on their own computer. You do not need to know how to write a program. Plan on about 20 minutes. The free parts need no API key and no money.

    Anubys is in private beta. MIT license planned. The public install opens soon. The program you type is called harness. The project folder is named ci-agent-regression-harness. Both of those names mean Anubys.

    The same steps are in docs/GETTING_STARTED.md (private beta). That file is the canonical source. These checks are also listed on the use cases page.

    What Anubys does

    Anubys compares a new version of an AI agent with the version you already trust. You give it scenarios, which are practice tasks with a known shape. It runs the The agent you already trust. (the trusted agent) and the The new agent you are considering. (the new agent) on those same tasks. The comparison ends as one verdict.

    text

    your agent -> scenarios -> baseline vs candidate -> one verdict

  Pass
  Block
  Insufficient evidence
  Invalid run

    Those are the only four verdicts. In files they are spelled pass, block, insufficient_evidence, and invalid_run.

    The four verdicts.
    VerdictIn plain words
    Pass The new agent was close enough to the current one that this test says go ahead.
    Block The new agent was clearly worse than the current one, so this test says stop.
    Insufficient evidence This test cannot yet tell whether the new agent is close enough, so it is not a yes or a no.
    Invalid run The test run itself was not reliable, so this result should not be used to decide.

    The check a results file section prints the verdict from the sample file with scripts/show_verdict.py. Suite scoring, statistics, and report rendering are still placeholders.

    Sample use cases

    Run these from the project folder, with the virtual environment on. The free commands before the live-model section do not call a model, and they do not spend money. They were checked with GEMINI_API_KEY unset. The dry run on this page was checked on Python 3.12.3. The other free commands on this page were checked on Python 3.11.

    python -m harness runs the program even if the harness command is not on your PATH. After Option B, harness and python -m harness do the same job. The samples use python -m harness.

    Why you'd use this

    These are the jobs Anubys is for. The command that runs a suite is python -m harness run. It writes run_summary.json when a run actually starts. It does not choose a verdict yet and it does not write results.json. The free step is a dry run, which prints the plan and does not call a model.

    A prompt tweak on a support bot

    You change the wording your support bot uses when a customer asks for a refund, and you want to know if the new wording still handles the practice chats. Example: 12 chats. The free step is a dry run. A live run of those chats costs money.

    Comparing two model settings

    You keep the same tasks and try two settings, one steadier and one more free. Example: temperature 0.2 and temperature 0.8. A dry run prints the plan for the model id you pass. It does not call the model. A live comparison costs money.

    Gating a side-project pull request

    You want the pull request to wait for one of the four verdicts, and you want Block to stop the merge. Example: one candidate against the baseline you already trust. harness run does not write that verdict yet. The GitHub Action that would block a merge is still a stub.

    Preview a run without calling a model

    You want the plan for a small live run: which scenarios would be selected, and the upper bound on cost. You do not want a model call, and you do not want to spend money.

    This is the only harness run step on this page. It is a dry run. Live mode still needs --ceiling, even on a dry run. The plan uses that number as the per-rollout limit when it prints the upper bound. The dry run does not reserve spend against the monthly check, and it does not call the model. It does not need a key, it does not add a spend row, and it does not create a runs/ directory. Copy the model id from config/allowed_models.txt. The command does not fill one in for you.

    shell

    python -m harness run suites/tau_retail --model "<id from config/allowed_models.txt>" --mode live --out runs/plan --limit 3 --rollouts 1 --ceiling 1 --dry-run

    This prints a plan and exits. It does not call a model, does not create runs/plan, and does not add a row to the spend log. The cost of this command is Example $0.

    Leave --ceiling in the command. Without it the command stops with an error and does not print the plan. The error says live mode requires --ceiling. Example: with --ceiling 1, --limit 3 and --rollouts 1, the plan's upper bound is $3. That is a cap on the plan, not a charge.

    You should see a plan. The block below is an Example. Where it shows <the id you passed>, your output has the id you copied from the allowlist. Every rate and total below is an Example. One allowlisted id printed input 0.30, output 2.50, and cached 0.03. Another id can print different rates.

    Spend safety

    Two checks sit in front of a live rollout.

    Per-rollout dollar limit. A live rollout can be given a dollar ceiling. It is checked after each model call, and the call that crosses it is included, so the rollout can cost slightly more than the ceiling. Anubys records the reason spend_ceiling. On main today that rollout is recorded as a miss. It is being changed to count as a fail (team decision October 16). The cost is still written to the spend log. The suite can continue with the next rollout. That miss or fail is a result for one rollout. The suite verdict is still only Pass, Block, Insufficient evidence, or Invalid run.

    The Example $38 monthly check. The Example $38 monthly check stops new live rollouts once logged spend reaches Example $38 and can overshoot slightly. Anubys adds up spend/spend_log.jsonl for the current calendar month in UTC. Before it starts a new live rollout, it also adds what that rollout is allowed to cost: your per-rollout ceiling, or the cost of the previous logged row when no ceiling is set. If that sum would reach Example $38, the next rollout does not start. A rollout that has already started is allowed to finish, so the logged total can end a little above Example $38.

    A budget alert in Google's own console does not stop the calls. The monthly check is what stops new live rollouts, and a small overshoot is possible.

    You can run the monthly check itself for free. It only reads the log. Stay in the project folder. The key can stay unset.

    shell

    python scripts/check_monthly_spend.py --threshold 38

    This sums the log for the current UTC month and compares it with Example $38. It does not call a model.

    The check on 16 October 2026 printed:

    output

    Example

    2026-10 logged spend is $0, under the $38 cap.

    Your line can start with a later month, such as the month you run it. Example $0 means the log has no spend in that month. The log file in the repository is empty until a labeled experiment appends a row. Leave the file alone.

    Start free (no account, no key, Example $0)

    Everything in the free use cases above runs offline. Those checks read files already in the project, so they never call an AI model and can't cost you anything. You don't need an API key for any of it. The only harness run step in that list is --dry-run. Replay is not a free beginner step. No sample recording ships, and replay refuses without model.json. A replay costs Example $0 only after a live run with --record has written that file.

    Costs money: live runs with a Gemini key

    A live run sends real requests to Google's Gemini model, and Google bills you for each one. Do not start one from this page. The approved path is .github/workflows/experiment.yml on main, in the live-experiments environment, after a required reviewer approves the run.

    1. Get a key. Sign in at Google AI Studio and create an API key. Think of it like a password that can spend your money.
    2. Store it in your terminal, never in a file you share. Do not run these lines during the free steps. A placeholder still makes the free check print set.

      Mac/Linux. This only lasts until you close the terminal, which is a good thing.

      shell · placeholder

      export GEMINI_API_KEY="paste-your-key-here"

      Windows (PowerShell):

      PowerShell · placeholder

      $env:GEMINI_API_KEY="paste-your-key-here"
    3. Never paste the key into code, a config file you commit, a screenshot, a chat, or a GitHub issue. If it leaks, delete it in AI Studio and make a new one.
    4. Set a budget alert. In the Google Cloud console, go to Billing, then "Budgets & alerts", and set a small monthly budget (for example Example $5). Heads-up: Google only emails you when you cross it. It does not stop spending.
    5. Know what stops spending. Anubys has its own spend limit for each test rollout. That limit is checked after each model call, and the call that crosses it is included, so the rollout can cost slightly more than the limit. The other gate settings live in suite.yaml. On main today, a rollout that goes over that limit is recorded as a miss. It is being changed to count as a fail (team decision October 16). The Example $38 monthly check stops new live rollouts once logged spend reaches Example $38, and the month can overshoot slightly. Your own budget is still on you. This page does not ask you to start a live run.

    What does a run cost?

    Real figures go here once the team's measured cost runs are done. Until then, treat any dollar amount in this guide as an Example, not a quote. The Example $38 monthly check is a limit in the tool, not a price for a run.

    Free tier vs paid

    Google AI Studio has a free tier with low rate limits. If you turn on billing, every request is charged, so set the budget alert first. This page does not ask you to start a live run.

    Glossary

    Scenario. One practice task: a customer situation, the tools the agent may use, and the checks Anubys applies to the outcome.

    Baseline. The agent you already trust. Anubys compares the new agent against it.

    Candidate. The new agent you are considering.

    Verdict. The single decision for a comparison. It is Pass, Block, Insufficient evidence, or Invalid run. Block: clearly worse, by more than the allowed margin.

    Rollout. One try of one scenario by one agent. A live rollout can call a model. The free commands on this page do not run rollouts. The dry run only prints a plan.

    Sanitization gates. The six safety checks in python -m harness gates: file shape, synthetic personal data, secrets, exact copies, near copies, and one split per family.

    Virtual environment. A private folder of Python packages for this project, usually named .venv.

    Spend log. The file spend/spend_log.jsonl, an append-only list of what live runs cost. A live dry run does not add a row and does not need this file. A real live run refuses a missing log instead of treating it as Example $0. The file in the repository is empty. Replay of a model recording writes an Example $0 row. The monthly check reads this file.

    Cassette. A saved recording of a model run, stored as model.json. python -m harness run --mode replay reads it. No sample recording ships.

    tau-bench retail. A public set of shopping support tasks. This repository already contains a copy. convert-tau-retail --dry-run only counts that local copy.
