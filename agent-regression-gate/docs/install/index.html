    Prerequisites

    Python 3.11 or newer, git, and a virtualenv at the repository root. The install command below runs inside that virtualenv.

    GEMINI_API_KEY is only for a live run. The offline checks on this page do not call a model, so they do not need the key. Samples use the placeholder your-key-here. Do not commit a real key.

    Run it locally

    Commands below are the ones on harness main. Private beta. Public install opens soon.

    Clone (beta testing)

    Private beta. The repository is not public yet, so this command only works if you already have access. The public install opens soon.

    Clone the repository, then change into it.

    shell · (beta testing)

    git clone https://github.com/rphua-dev/ci-agent-regression-harness.git
cd ci-agent-regression-harness

    Install

    From the virtualenv at the repository root:

    shell

    python -m pip install --require-hashes -r requirements.lock
python -m pip install --no-deps -e .

    Verify the setup

    These checks stay offline. They do not call a model.

    shell

    pytest
python -m harness validate suites/tau_retail
python -m harness validate-results docs/examples/results.preliminary.json
python -m harness gates suites/tau_retail/scenarios
python scripts/check_monthly_spend.py

    harness run stops new live rollouts at a fixed $38. The standalone scripts/check_monthly_spend.py takes --threshold / MONTHLY_SPEND_CAP_USD. A run already in progress can finish, so the month can overshoot slightly. The same check is described on spend governance.

    The provider key

    Set GEMINI_API_KEY only when a live run calls the provider. The line below is a terminal export, never in a file. The placeholder is your-key-here.

    shell · placeholder

    export GEMINI_API_KEY="your-key-here"

    Never in a file. In CI the value is an environment secret on the live-experiments environment (main only, approving reviewer), never a repository secret.

    In CI, that value is an environment secret on the live-experiments environment. It is not a repository secret. Live runs are manual, on the experiment workflow (.github/workflows/experiment.yml). That workflow starts with the spend check. The model id is an explicit input, pinned, and checked against the allowlist (config/allowed_models.txt). Ids that contain latest, preview, or exp are rejected. There is no fallback.

    Read the verdict Coming soon

    A full gate on your machine is Coming soon. The rollout runner is implemented. Suite scoring, statistics, and report rendering are still placeholders. The only free run step is the dry run in the getting started guide.

    When a run does print a suite status, read it as one of four: Pass, Block, Insufficient evidence, or Invalid run. likely_regression is a warning. It is not a status. An invalid run is not scored. Scenario rows stay diagnostics. The rule is on Concepts.

    Enterprise and CI

    The packaged GitHub Action is Coming soon. The action/ directory is an intentional stub.

    CI on main is .github/workflows/ci.yml. It runs on pull requests and on pushes to main. The job is read-only (contents: read). The workflow has no secrets. A pull request run does not receive an OIDC token.

    A live model call is a different workflow. It is manual, it starts with the spend check, and it reads GEMINI_API_KEY from the live-experiments environment. Pull request runs never receive that secret. The spend check stops new live rollouts at Example $38 of logged spend this UTC month. A run already in progress can finish. The experiment workflow also has a dollar ceiling.

    Troubleshooting

    • Missing key. Offline checks do not need GEMINI_API_KEY. A live run does. If the variable is unset, the provider call cannot start. The placeholder is your-key-here. In CI the real value is an environment secret on live-experiments.
    • Spend cap stop. harness run stops new live rollouts at a fixed $38. The standalone scripts/check_monthly_spend.py takes --threshold / MONTHLY_SPEND_CAP_USD. A run already in progress can finish.
    • Insufficient evidence. The interval does not support Pass, and it does not support Block. likely_regression on that result is a warning, not its own status. Read the statuses on Concepts.
