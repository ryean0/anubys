    Writing scenarios

    A scenario names one situation, a reference path, and the outcome a pass must reach. Bring-your-own scenarios is Planned.

    On this page

    1. Scenario format
    2. Variants
    3. Bring your own

    Scenario format

    A scenario has scenario_id, family_id, variant_id, version, content_hash, environment.initial_state, reference_actions, and assertions. max_steps is a loop backstop, about 2x the reference actions.

    refund.v1

    scenario_id: refund.v1
family_id: refund
variant_id: v1
version: 3
content_hash: sha256:9f2c1a0e4b
environment:
  type: simulator
  initial_state:
    order: "1001"
reference_actions:
  - refund_payment
  - confirm_refund
assertions:
  - refund_issued
max_steps: 4

    Variants

    refund.v1, refund.v2, and refund.v3 are three variants of the family refund. Same family, different text.

    A hash mismatch makes the run invalid before a score is published. The recorded text has to match the suite.

    Bring your own Planned

    Bring-your-own scenarios is Planned. This page is the format for that work. There is not yet a loader for a scenario set you host yourself.
