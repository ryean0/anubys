    Adapter contract

    One rollout is one call. The adapter returns an outcome. The scorer sets the suite status.

    On this page

    1. One rollout
    2. Outcomes
    3. What the adapter does not decide

    One rollout

    The call carries the scenario id, the SHA-256 of the scenario text, the arm (baseline or candidate), and a step budget. The adapter returns one outcome. A step may record thinking_tokens and cached_tokens. Both are optional and may be null. thinking_tokens counts thoughts billed at the output rate. cached_tokens counts cached input tokens included in tokens_in. The site copy of that contract is schema/step.schema.json.

    rollout

    scenario_id: refund.v1
scenario_hash: sha256:9f2c1a0e4b
arm: candidate
step_budget: 10
outcome: pass

    Outcomes

    The outcome list matches Misses and fails. Fails score 0. Misses are excluded. Over the 5% cap on an arm, the run is invalid_run.

    Adapter outcomes
    OutcomeClass
    passScored, 1
    failFail, scored 0
    agent_timeoutFail, scored 0
    agent_errorFail, scored 0
    spend_ceilingError, scored 0
    infra_timeoutMiss
    rate_limitMiss
    http_5xxMiss
    ci_killMiss
    env_missMiss

    spend_ceiling is status error: it counts as an error, a failed rollout in the pass rate, not a miss. A rollout that already ended as an infrastructure miss stays a miss even if it also went over the ceiling.

    What the adapter does not decide

    The adapter does not set Pass, Block, Insufficient evidence, or Invalid run. The scorer does, from the pooled arms. The model name does not enter the suite status.
