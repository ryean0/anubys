    Schema 1

    Schema 1 is the original results file. This page reads it. The file carries version, status, level, likely_regression, and arms. status is preliminary or final. level is 0.9.

    likely_regression false is Pass. True is Block. Null, when the run is not invalid, is Insufficient evidence. invalid_run true is Invalid run.

    Schema 2.0.0

    Schema 2.0.0 adds an optional one-sentence caption on each scenario and arm, and an optional model_id on each arm. This page still reads 2.0.0. A model id is shown when it is present and does not change the suite status. The shipped sample is 2.1.0.

    results.json · 2.0.0

    {
  "version": "2.0.0",
  "status": "preliminary",
  "level": 0.9,
  "likely_regression": false,
  "invalid_run": false,
  "arms": {
    "baseline": {
      "scheduled_rollouts": 8,
      "environment_misses": 0,
      "miss_counts": {},
      "model_id": "a pinned Gemini Flash-Lite model id (lives in config/allowed_models.txt and is passed with --model)"
    },
    "candidate": {
      "scheduled_rollouts": 8,
      "environment_misses": 0,
      "miss_counts": {},
      "model_id": "a pinned Gemini Flash-Lite model id (lives in config/allowed_models.txt and is passed with --model)"
    }
  }
}

    Schema 2.1.0

    Schema 2.1.0 is the file this page reads, along with schema 1 and 2.0.0. It sets schema_version to 2.1.0. Model ids are recorded at verdicts.overall.model_ids for the baseline and the candidate, and at baseline_pool_model_id. run_kind selects the model-id rule. Screening, baseline, and aa share one model id across both arms. A gate run may use a different candidate id, and its baseline id must equal baseline_pool_model_id. There is no per-arm model_id on 2.1.0. delta and the confidence level are numbers on verdicts.overall. When they are missing the page shows δ = 5 pp / 90%. They do not change the suite status.

    results.json · 2.1.0

    {
  "schema_version": "2.1.0",
  "run_kind": "screening",
  "baseline_pool_model_id": "tau-retail-baseline-pool",
  "verdicts": {
    "overall": {
      "verdict": "insufficient_evidence",
      "likely_regression": false,
      "model_ids": {
        "baseline": "tau-retail-baseline-pool",
        "candidate": "tau-retail-baseline-pool"
      }
    }
  }
}

    The suite verdict is verdicts.overall.verdict: pass, block, insufficient_evidence, or invalid_run. likely_regression is a boolean on that verdict, not a fifth status. Diagnostics live on verdicts.diagnostics. The bundled rows include example.clean.v1 (family example.clean) and example.broken.v1 (family example.broken). A run summary is a separate file, run_summary.json, with schema_version 1.0.0. It is not a field of results.json. The results panel reads example summary data from data/run_summary.example.json. This is still schema 2.1.0.

    Still in progress, and not part of this 2.1.0 reader: a per-family estimate and interval, and cost per verdict. A family row has no verdict. The gate stays on the pooled result. Those fields are Next, by October 29. Showing the MDE on the check is planned with Milestone B (target November 10).
