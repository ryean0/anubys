    Quickstart

    Five steps: add the workflow, add the adapter, allowlist the model, set the secret, open a PR. You cannot wire your own agent or repository on this check today. The packaged Action is a stub until about November 5. Bring-your-own scenarios is post-MVP. Anything not shipped yet is marked Planned.

    On this page

    1. Add the workflow
    2. Add the adapter
    3. Allowlist the model
    4. Set the secret
    5. Open a pull request

    Add the workflow Planned

    Add a workflow that runs on pull_request. The packaged Action that does this in one file is Planned, a stub until about November 5. This page does not wire your own agent or repository today. Bring-your-own is post-MVP. The shape below is the job: OIDC for a later role, and a read-only pull-request role. Pull-request CI is contents: read and does not receive an id-token.

    workflow.yml · Planned

    name: anubys
on:
  pull_request:
permissions:
  contents: read
  id-token: write
  pull-requests: read
jobs:
  gate:
    name: Anubys
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      # Planned: a packaged Action, one file.
      # The job requests an OIDC token.
      # It does not store a cloud key.

    The CI reference is the same contract. workflow_dispatch on a pull-request branch does not satisfy a required check.

    Add the adapter Built

    Add the adapter. Gemini is the reference: one adapter, and one allowlist entry. The adapter runs a scenario and returns one outcome. It does not decide the suite status.

    config/allowed_models.txt

    <pinned Gemini Flash-Lite id>

    passed with --model (listed in config/allowed_models.txt and passed with --model). The contract is on the adapter reference. A second provider is Planned.

    Allowlist the model Built

    Allowlist the model id the adapter may call. The shipped entry is a pinned Gemini Flash-Lite model id (exact version set in suite config). A floating alias is not the pin.

    OpenAI and Anthropic are not on the allowlist. That second provider is Planned.

    Set the secret In progress

    GEMINI_API_KEY goes in an environment secret on the live-experiments environment (main only, approving reviewer), never a repository secret, never a file.

    Keyless CI (OIDC): roles deployed, CI wiring in progress. Spend governance is Built. The audit trail is in progress. Data stays in your cloud is Planned, and post-MVP.

    Open a pull request Planned

    Open a PR. The check is meant to run on that event and post one suite status. Requiring the check waits on the packaged Action, which is Planned.

    Today harness run writes run_summary.json, not a verdict. The harness will write the results file once scoring lands. Replace that file in place when the scorer is ready. The page does not change.
