Sample use cases

(beta testing)

Try the free checks.

Run these from the project folder, with the virtual environment on. They do not call a model, and they do not spend money. The free commands before the live-model section were checked with GEMINI_API_KEY unset. The dry run on this page was checked on Python 3.12.3. The other free commands on this page were checked on Python 3.11.

Anubys is in private beta. MIT license planned. The public install opens soon. There is no pip install anubys package on the public Python package index. Not on PyPI yet. PyPI v0.1 is planned for November 16 to 20. Suite scoring, statistics, and report rendering are still placeholders. The command that runs a suite is python -m harness run. It writes run_summary.json and does not choose a verdict yet. Install steps, including the private-repo warning, are in the getting started guide. The canonical write-up is docs/GETTING_STARTED.md (private beta).

python -m harness runs the program even if the harness command is not on your PATH. After you download the repository, harness and python -m harness do the same job. The samples use python -m harness.

Why you'd use this

These are the jobs Anubys is for. The command that runs a suite is python -m harness run. It writes run_summary.json when a run actually starts. It does not choose a verdict yet and it does not write results.json. The free step is a dry run, which prints the plan and does not call a model.

A prompt tweak on a support bot

You change the wording your support bot uses when a customer asks for a refund, and you want to know if the new wording still handles the practice chats. Example: 12 chats. The free step is a dry run. A live run of those chats costs money.

Comparing two model settings

You keep the same tasks and try two settings, one steadier and one more free. Example: temperature 0.2 and temperature 0.8. A dry run prints the plan for the model id you pass. It does not call the model. A live comparison costs money.

Gating a side-project pull request

You want the pull request to wait for one of the four verdicts, and you want Block to stop the merge. Example: one candidate against the baseline you already trust. harness run does not write that verdict yet. The GitHub Action that would block a merge is still a stub.

Preview a run without calling a model

You want the plan for a small live run: which scenarios would be selected, and the upper bound on cost. You do not want a model call, and you do not want to spend money.

This is the only harness run step on this page. It is a dry run. Live mode still needs --ceiling, even on a dry run. The plan uses that number as the per-rollout limit when it prints the upper bound. The dry run does not reserve spend against the monthly check, and it does not call the model. It does not need a key, it does not add a spend row, and it does not create a runs/ directory. Copy the model id from config/allowed_models.txt. The command does not fill one in for you.

shell

python -m harness run suites/tau_retail --model "<id from config/allowed_models.txt>" --mode live --out runs/plan --limit 3 --rollouts 1 --ceiling 1 --dry-run

This prints a plan and exits. It does not call a model, does not create runs/plan, and does not add a row to the spend log. The cost of this command is Example $0.

In a checkout, the live spend log is spend/spend_log.jsonl. Outside a checkout, the live log is ~/.anubys/spend_log.jsonl and nothing else. No environment variable or setting changes it, and a live run refuses any other --spend-log, including ./spend/spend_log.jsonl. That log is per user and per machine, so two machines do not share a total. The first live run outside a checkout creates ~/.anubys with mode 0700 and an empty log. If ~/.anubys already exists and the log is missing, the run refuses instead of treating the gap as Example $0. The Example $38 check still runs before each rollout.

Leave --ceiling in the command. Without it the command stops with an error and does not print the plan. The error says live mode requires --ceiling. Example: with --ceiling 1, --limit 3 and --rollouts 1, the plan's upper bound is $3. That is a cap on the plan, not a charge.

You should see a plan. The block below is an Example. Where it shows <the id you passed>, your output has the id you copied from the allowlist. Every rate and total below is an Example. One allowlisted id printed input 0.30, output 2.50, and cached 0.03. Another id can print different rates. The pricing_file line names the file the plan read. In a checkout that is config/gemini_pricing.yaml. An installed wheel prints harness/data/gemini_pricing.yaml.

output · Example

plan

On the current retail suite, --limit 3 keeps the first three scenario ids in sorted order. The command finishes after the plan. Replay is not a free first step.

Check that the example scenarios are valid

You want to know that the small set of example shopping tasks is written in the shape Anubys accepts.

shell

python -m harness validate suites/tau_retail/examples

This reads the example files and checks their shape. It does not run an agent.

You should see:

output

ok 9 scenario(s), 0 suite file(s)

That means all 9 example files are valid.

The same check covers the larger retail folder and its suite file. This walks the whole retail suite, including the examples and the scenario set used by the safety checks.

shell

python -m harness validate suites/tau_retail

You should see:

output

ok 87 scenario(s), 1 suite file(s)

That means 87 scenario files and 1 suite file passed. The 9 example files and the 78 files in the scenarios folder are those 87.

More detail on the file shape is in docs/scenario-format.md (private beta).

Run the safety checks

You want to know the sanitized scenarios are safe to keep: the shape is valid, the personal data is synthetic, there are no secrets, and the tasks are not copies of each other.

Use validate on examples, gates on scenarios. Mixing them up gives a scary but harmless failure.

shell

python -m harness gates suites/tau_retail/scenarios

This runs six safety checks on the scenarios folder. It does not call a model. Gitleaks, an optional extra secret scanner, is not required on your own computer.

You don't need to understand every line. This command is python -m harness gates suites/tau_retail/scenarios. Look for ok 6 gate(s) at the end of its output. That line is from this command only.

You should see:

output

schema: pass (78 scenario(s), 0 suite file(s))
synthetic-pii: pass (78 scenario(s), 0 cassette file(s))
secrets: pass (python scanner; gitleaks not installed, trufflehog not installed; 78 file(s))
exact-duplicates: pass (78 scenario(s), canonical content hash)
near-duplicates: pass (78 scenario(s), MinHash on user turns, threshold 0.8)
splits: pass (26 family(ies), one split each)
ok 6 gate(s)

ok 6 gate(s) is the last line of python -m harness gates suites/tau_retail/scenarios only. It means every check passed. gitleaks not installed and trufflehog not installed are normal on a laptop. The secrets line still says pass. The project's CI installs gitleaks and adds --require-gitleaks. You can leave that flag off.

Running python -m harness gates suites/tau_retail/examples is a different command. This is on purpose: the examples deliberately contain fake personal data, so the output is a long list of synthetic names and addresses, and the last line is:

output

1 gate(s) failed: synthetic-pii

Check a results file and read its verdict

You have a results file and you want the verdict in plain words. The file in the repository is practice data for a demo page. It is not a score from a real agent.

shell

python -m harness validate-results docs/examples/results.preliminary.json

This checks that the results file has the fields Anubys expects. It does not print the verdict.

You should see:

output

ok 1 results file(s)

That means the file is valid. Read the verdict with:

shell

python scripts/show_verdict.py docs/examples/results.preliminary.json

This opens the results file and prints the verdict word plus one plain sentence.

You should see:

output

insufficient_evidence
This test cannot yet tell whether the new agent is close enough, so it is not a yes or a no.

That is Insufficient evidence: the test cannot yet say yes or no. The file itself says the numbers are fake practice data, so this is not a real comparison. The field guide for the file is docs/results-format.md (private beta).

Replay a recorded run Built

Replay is not a free first step. python -m harness run --mode replay reruns a saved model recording without calling a model. That costs Example $0 only after you already have one. A live run with --record writes it as model.json in the cassettes folder, and no sample recording ships. Without model.json, replay refuses before any rollout. Replaying only the tool environment while the model is live still calls the model and can spend money.

Skip replay until you have your own recording. This page does not ask you to make one.

Preview converting tau-bench retail tasks

You want a preview of how the vendored tau-bench retail tasks would be classified, without writing files and without spending money.

shell

python -m harness convert-tau-retail --dry-run

This counts the local retail tasks on the test split and prints three policy labels. --dry-run writes nothing. The tasks are already in the repository, so this does not download them and does not call a model.

You should see:

output

split test: 115 tasks
  allowed: 104
  must_refuse: 7
  ambiguous: 4

The 115 is the original tau-bench task list. The 87 earlier are the scenarios Anubys converted from it, so the numbers are not supposed to match.

That means the test split has 115 tasks: 104 the agent may carry out, 7 the agent must refuse, and 4 that are ambiguous. No scenario files were written. Stop here for the preview. Adding --out would write files, and this page does not ask you to do that.

Run against a real model (costs money)

Costs money

A live run sends tasks to Google Gemini and can charge the Google account that owns the API key. Read this section so you know how the guard rails work. Do not start a live run from this page.

python -m harness run --mode live is the command that calls the model. It needs GEMINI_API_KEY in the current terminal and --ceiling. A live run that starts writes run_summary.json. It does not write a verdict. The approved path for a paid run is the manual workflow .github/workflows/experiment.yml, started from main in the live-experiments environment after a required reviewer approves it. Do not start a live run from this page.

The steps below only explain the key and the free spend check. They are not a live run.

Get a Gemini API key

  1. Sign in to Google AI Studio.
  2. Open the API keys page and create a key. Google's steps are in the Gemini API key guide.
  3. Copy the key once. Keep it in the A window where you type one line, press Enter, and read the reply. only.

Keep the key out of the project

Paste the key only into the current terminal, never into a file you could commit. Do not put it in a scenario, in spend/spend_log.jsonl, or in a note.

Do not paste the export or $env:GEMINI_API_KEY lines during the free steps. The placeholder text still counts as a key. The free check then prints set instead of missing. Leave the key unset until you mean to do a live run. A check with GEMINI_API_KEY set to paste-the-key-here printed set. With the key unset, it printed missing.

Use the left and right arrow keys to change the computer. Home and End jump to the first and last choice.

Spend safety

Two checks sit in front of a live rollout.

Per-rollout dollar limit. A live rollout can be given a dollar ceiling. It is checked after each model call, and the call that crosses it is included, so the rollout can cost slightly more than the ceiling. Anubys records that rollout as an error with reason spend_ceiling. It counts as an error: a failed rollout in the pass rate, scored 0. It is not an environment miss, and it does not count toward the miss cap. A rollout that already ended as an infrastructure miss, such as a provider 5xx, stays a miss even if it also went over the ceiling. The cost is still written to the spend log. The suite can continue with the next rollout. That error is a result for one rollout. The suite verdict is still only Pass, Block, Insufficient evidence, or Invalid run.

The Example $38 monthly check. The Example $38 monthly check stops new live rollouts once logged spend reaches Example $38 and can overshoot slightly. In a checkout, Anubys adds up spend/spend_log.jsonl for the current calendar month in UTC. Outside a checkout the same check reads ~/.anubys/spend_log.jsonl. That log is per user and per machine, so two machines do not share a total. Before it starts a new live rollout, it adds the per-rollout --ceiling to that sum. Live mode requires --ceiling, so that ceiling is the amount reserved for the rollout. If the sum would reach Example $38, the next rollout does not start. A rollout that has already started is allowed to finish, so the logged total can end a little above Example $38.

A budget alert in Google's own console does not stop the calls. The monthly check is what stops new live rollouts, and a small overshoot is possible.

You can run the monthly check itself for free. It only reads the log. Stay in the project folder. The key can stay unset.

shell

python scripts/check_monthly_spend.py --threshold 38

This sums the log for the current UTC month and compares it with Example $38. It does not call a model.

The check on 16 October 2026 printed:

output

Example

2026-10 logged spend is $0, under the $38 cap.

Your line can start with a later month, such as the month you run it. Example $0 means the log has no spend in that month. The log file in the repository is empty until an approved live run appends a row. Leave the file alone.

Keeping it free and safe

Start free (no account, no key, Example $0)

Everything in the free use cases above runs offline. Those checks read files already in the project, so they never call an AI model and can't cost you anything. You don't need an API key for any of it. The only harness run step in that list is --dry-run. Replay is not a free beginner step. No sample recording ships, and replay refuses without model.json. A replay costs Example $0 only after a live run with --record has written that file.

Costs money: live runs with a Gemini key

A live run sends real requests to Google's Gemini model, and Google bills you for each one. Do not start one from this page. The approved path is .github/workflows/experiment.yml on main, in the live-experiments environment, after a required reviewer approves the run.

  1. Get a key. Sign in at Google AI Studio and create an API key. Think of it like a password that can spend your money.
  2. Store it in your terminal, never in a file you share. Do not run these lines during the free steps. A placeholder still makes the free check print set.

    shell · placeholder

    export GEMINI_API_KEY="paste-your-key-here"

    PowerShell · placeholder

    $env:GEMINI_API_KEY="paste-your-key-here"

    This only lasts until you close the terminal, which is a good thing.

  3. Never paste the key into code, a config file you commit, a screenshot, a chat, or a GitHub issue. If it leaks, delete it in AI Studio and make a new one.
  4. Set a budget alert. In the Google Cloud console, go to Billing, then "Budgets & alerts", and set a small monthly budget (for example Example $5). Heads-up: Google only emails you when you cross it. It does not stop spending.
  5. Know what stops spending. Anubys has its own spend limit for each test rollout. That limit is checked after each model call, and the call that crosses it is included, so the rollout can cost slightly more than the limit. The other gate settings live in suite.yaml. A rollout that goes over that limit is recorded as an error with reason spend_ceiling. It counts as an error (a failed rollout in the pass rate) and stays out of the environment-miss count. The Example $38 monthly check stops new live rollouts once logged spend reaches Example $38, and the month can overshoot slightly. Your own budget is still on you. This page does not ask you to start a live run.

What does a run cost?

Real figures go here once the team's measured cost runs are done. Until then, treat any dollar amount in this guide as an Example, not a quote. The Example $38 monthly check is a limit in the tool, not a price for a run.

Free tier vs paid

Google AI Studio has a free tier with low rate limits. If you turn on billing, every request is charged, so set the budget alert first. This page does not ask you to start a live run.
